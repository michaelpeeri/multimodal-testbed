## 1. `_fixed_point_iterate` (models.py:145-168)

```python
def _fixed_point_iterate(f, z0, max_iter=30, tol=1e-4):
  z = z0
  for i in range(max_iter):
    z_next = f(z)
    rel_change = ((z_next - z).norm() / (z.norm() + 1e-6)).item()
    z = z_next
    if rel_change < tol:
      n_iter = i + 1
      break
  return z, n_iter, rel_change
```

This is plain **Picard iteration** / repeated substitution: given some function `f`, start from `z0` and keep applying `f` until the relative change between successive iterates drops below `tol`. It's a generic solver — it doesn't know anything about VAEs; it's used twice in `DEQCell` (once for the forward solve, once for the backward solve — see below). It only converges if `f` is a **contraction** (Lipschitz constant < 1), which is guaranteed by construction in `DEQCell._f`. This is a verbatim copy of the same helper already used by `DEQBlock` in `normalizing_flow_demo.py` — duplicated locally rather than imported, because importing that module would execute its entire top-level training demo as a side effect.

## 2. `DEQCell` (models.py:171-242)

This is the actual "DEQ" building block — a **weight-tied recurrent cell** solved to its fixed point instead of unrolled a fixed number of times.

**Constructor (198-211):**
```python
self.W_zz = nn.utils.spectral_norm(nn.Linear(dim, dim, bias=False), n_power_iterations=n_power_iterations)
```
`spectral_norm` rescales `W_zz`'s weight matrix on every forward pass so its operator norm (largest singular value) is ≤ 1. Combined with `coeff` (default 0.9) and the fact that `tanh` is itself 1-Lipschitz, the composed map

```python
def _f(self, z, c):
    return self.coeff * torch.tanh(self.W_zz(z) + c)
```

has Lipschitz constant ≤ `coeff` < 1 **in `z`** (for any fixed `c`). By the Banach fixed-point theorem, this guarantees `z* = f(z*, c)` has a *unique* solution and that Picard iteration converges to it geometrically. This is the exact same argument `LipschitzMLP`/`DEQBlock` use in `normalizing_flow_demo.py` — I'm reusing the trick, just without the invertibility requirements a flow needs.

**Forward pass (216-242)** — this is the standard 3-step DEQ pattern from Bai, Kolter & Koltun (2019):

```python
z0 = torch.zeros_like(c)
with torch.no_grad():
    z_star, n_iter, residual = _fixed_point_iterate(lambda z: self._f(z, c), z0, ...)
```
Step 1: solve for the fixed point **with gradients disabled**. This is the expensive part (up to 30 iterations), but since it's under `no_grad`, PyTorch never builds an autograd graph through it — cheap in memory regardless of iteration count.

```python
z = self._f(z_star, c)  # value ~= z_star, but now differentiable
```
Step 2: re-apply `_f` *once more* at the converged (but now detached-from-history) `z_star`, this time with gradients enabled. Since `z_star` is already at (or extremely near) the fixed point, `z ≈ z_star` numerically, but now `z` has a *shallow* one-step graph connecting it to `c` and to `W_zz`'s parameters — not a 30-step unrolled graph.

```python
if z.requires_grad:
    z0d = z.detach().requires_grad_()
    f0 = self._f(z0d, c)
    def backward_hook(grad):
        v, ... = _fixed_point_iterate(
            lambda v: torch.autograd.grad(f0, z0d, grad_outputs=v, retain_graph=True)[0] + grad,
            grad, ...)
        return v
    z.register_hook(backward_hook)
```
Step 3 is the actual "implicit differentiation" trick, and it's the reason step 2's one-step graph gives the *correct* gradient despite skipping the 30-step unroll. Mathematically: if `z* = f(z*, c)`, then by the implicit function theorem,
```
dz*/dc = J^T · (dz*/dc) + (∂f/∂c)      where J = ∂f/∂z at z*
=>  (I - J^T) · dz*/dc = ∂f/∂c
```
So to get the correct gradient w.r.t. any upstream loss, incoming gradient `grad = dL/dz*` must be transformed into `v = (I - J^T)^{-1} · grad` before it's allowed to flow further backward. Computing `(I - J^T)^{-1}` explicitly would need a full Jacobian; instead, `register_hook` intercepts the gradient at exactly this point in the graph and solves `v = J^T·v + grad` **by fixed-point iteration** (a Neumann-series expansion of `(I-J^T)^{-1} = I + J^T + (J^T)^2 + ...`, which converges because `J^T` also has spectral norm < 1 for the same reason `f` is a contraction). `torch.autograd.grad(f0, z0d, grad_outputs=v)` computes `J^T · v` via a vector-Jacobian product, without ever materializing `J` as a matrix. Once `v` converges, it's returned as the "true" gradient for `z`, and normal backprop continues through it into `c` and `W_zz`.

Net effect: forward cost is O(30 iterations) but O(1) graph depth; backward cost is another ~30-iteration solve, but also O(1) graph depth — this is exactly what makes DEQs "infinite depth" without infinite memory/compute cost per step.

The `last_forward_iters` / `last_forward_residual` (and backward equivalents) are just instrumentation — they record how many iterations were actually needed and how close to convergence it got, so you can inspect solver health later (e.g. via `model.deq_cell.last_forward_iters`).
